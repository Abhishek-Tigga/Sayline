| 2026-08-08 | Cleanup | Replaced the word-overlap "suspicious deviation" backstop with a real edit-validated cleanup pass (`TranscriptCleanupValidator`). Word-level LCS diff between the raw transcript and the LLM's cleaned output; only whitelisted edits survive — filler-word deletion, adjacent repeat/false-start deletion, punctuation/capitalization changes, near-word substitutions (edit-distance-bounded, catches things like dont→don't) — every other edit reverts to the original wording. Makes the two live complaints (over-cleaning that cuts real words, and the model answering a dictated question instead of cleaning it) structurally impossible instead of prompt-discouraged. Verified by running the actual compiled validator (not just a model of it) against both real historical failures plus two synthetic cases the old 35%-new-word-ratio heuristic was proven to miss — the substantive-question failure now reverts word-for-word to the original question, and the vocabulary-reusing synthetic case is caught (previously slipped through at 0% new words). | 2026-08-08 | Cleanup | Rewrote `TranscriptCleanupValidator` to a two-tier design after live testing showed the first version's word-by-word merge left punctuation/casing mangled wherever a raw word got restored ("Is It better to commit now. or wait until tomorrow?"). Now: (1) a compliance gate scores what fraction of the raw transcript was touched by disallowed edits — over 30%, the LLM output is discarded entirely and a deterministic `tidy()` pass runs on the raw transcript instead (no merge, no seams); (2) below the gate, a smoothing pass fixes casing/punctuation at the remaining seams (strips stray mid-sentence punctuation, takes casing authority from the raw word at non-sentence-boundary positions). Also widened the edit whitelist (bigram fillers "you know"/"I mean"/"sort of"/"kind of", sentence-initial "so"/"well"/"okay", up to 2 small grammar-word insertions per call) and added a false-start rule (drops a ≤3-word deleted run that ends by repeating the last kept word, catching real restarts like "I went to— I drove to the store"). Verified by running the actual compiled validator against 7 cases (both real historical failures and synthetic ones) — the toolfolio.com meta-answer failure now fully reverts to a clean "What if I open toolfolio.com?" instead of the previous messy partial merge, and the "maybe get lunch"-drops-a-real-word guarantee still holds |

| 2026-08-09 | Agent mode | Three follow-up fixes after live testing of the dynamic pane catalog, each traced from captured app logs rather than guessed. (1) **Pane matching was far too brittle** — exact-normalized comparison alone meant "keyboard settings", "display", "Dock", "storage settings", and "General" all fell through to the failure path despite naming real panes. Matching is now three-stage: whole-string normalized (keeps "wifi" → "Wi-Fi" working, which token-splitting would break), then a small hand-written alias table, then token-subset matching with noise words ("settings", "the", "my") stripped and crude consistent singularization. Verified against previously-broken cases, a regression set of cases that already worked, and a set that must *not* match ("System Settings", "banana") so they still reach the fallback. (2) **The fallback was deceptive** — it opened System Settings via the bare `x-apple.systempreferences:` URL, which restores the last-viewed pane, so asking for a nonexistent pane surfaced an unrelated one (reported live: "open general settings" opened Screen Time). It now opens nothing and relies on the flash message alone; a wrong pane reads as a wrong answer, which is worse than visibly doing nothing. (3) **The `tool_use_failed` retry added a day earlier was useless** — it re-sent an identical request at the same `temperature: 0.1`, where the model is near-deterministic, and the log showed the retry reproducing a byte-identical malformed generation. The retry now samples at `temperature: 0.6`; the first attempt stays at 0.1 so normal routing keeps its predictability. Also corrected two display names against the real macOS 26 UI: "Desktop" → "Desktop & Dock" and "Siri" → "Apple Intelligence & Siri". Separately established that macOS has **no General pane at all** — verified by testing every plausible identifier (`com.apple.systempreferences.GeneralSettings` and `com.apple.General-Settings.extension` both open an empty window; legacy `com.apple.preference.general` has been reassigned to Appearance) — it's a sidebar category, so "general settings" is aliased to About, the first pane inside it |
